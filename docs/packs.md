# Пакети, каталог, карти й моделі

## Пакет

Пакет — тека з `manifest.json` і файлами. Кожен файл має розмір і SHA-256,
тому пакет можна докачувати по файлах і перевіряти після флешки.

```json
{
  "id": "pocket-uk", "tier": "pocket", "kind": "content",
  "title": "Кишеньковий набір", "version": "0.1.0",
  "content_license": "CC-BY-4.0",
  "files": [{"path": "cards/first_aid.json", "size": 1234, "sha256": "…"}]
}
```

| `kind` | Що всередині |
|---|---|
| `content` | `cards.json` або `cards/*.json`, `articles/**/*.md`, довідники `*.zim` |
| `map` | `*.pmtiles` (растрові тайли), поле `region` = id області з `regions.rs` |
| `model` | `*.gguf` або `*.litertlm`, поле `model_id` = id з каталогу моделей |

## Підпис

SHA-256 лише ловить пошкодження: хто підмінив файл, підмінить і маніфест.
Тому кожен маніфест підписаний ключем проєкту (Ed25519, поле `signature`), а
застосунок і хаб перевіряють підпис вбудованими публічними ключами
(`core/crates/uautonomy-core/assets/keys/trusted.json`) **до** завантаження й
ще раз перед встановленням: з інтернету, з хаба, з іншого телефона по Wi-Fi
і з флешки однаково.

- Підпис охоплює id, рівень, тип, назву, опис, версію, ліцензію, область,
  модель, дату підпису й усі файли з розміром і SHA-256. Пряма адреса файлу
  (`url`) не входить: файл однаково звіряється з підписаним SHA-256.
- Дата підпису (`issued`) не дає поставити старішу редакцію поверх новішої
  (наприклад, повернути відкликану картку). Свідомо повернути стару можна,
  лише видаливши пакет.
- Пакети без дійсного підпису (зі старих тестових збірок) застосунок не
  читає й не роздає; на екрані «Пакети» вони позначені ⚠, їх варто видалити.
- Каталог з інтернету (https) має поруч `catalog.json.sig`, без нього
  каталог не відкривається. Каталог іншого телефона чи хаба (http у локальній
  мережі) складається на ходу й не підписаний, але кожен пакет у ньому
  підписаний окремо.

Подробиці про ключі, секрети й резервні копії: [signing.md](signing.md).

## Виправлення вбудованих карток

Картка чи стаття з тим самим `id` у підписаному пакеті вмісту замінює
вбудовану: у списку, у пошуку й у контексті ШІ лишається лише нова редакція.
Так термінове виправлення доходить без нового APK, у тому числі
телефон-телефон. Якщо кілька пакетів мають ту саму картку, перемагає пакет із
новішим підписом.

## Оновлення без втрати пакета

Нова версія збирається в окремій теці. Потім стара тека відсувається в
`staging/<id>~old`, нова перейменовується на місце, стара видаляється. Якщо
живлення зникне посередині, під час наступного запуску `PackStore::open`
поверне стару версію або доведе заміну до кінця. Завершені файли
завантаження лишаються, тож повтор не качає їх знову.

## Файл .uapack

Один файл `.uapack` — це звичайний tar без стиснення, де першим іде
`manifest.json`. Його зручно носити на флешці; застосунок імпортує і теку, і `.uapack`.

## Інструменти (хаб)

```sh
cd core
cargo run -p uautonomy-hub -- pack    ../build/pocket --id pocket-uk --title "Кишеньковий" --tier pocket
PACK_SIGNING_KEY=… cargo run -p uautonomy-hub -- sign ../build/pocket
cargo run -p uautonomy-hub -- export  ../build/pocket pocket-uk.uapack
PACK_SIGNING_KEY=… cargo run -p uautonomy-hub -- catalog ../build --base-url https://example.org/packs --sign-key-env PACK_SIGNING_KEY
cargo run -p uautonomy-hub -- verify  ../build/catalog.json
cargo run -p uautonomy-hub -- install --data /srv/autonomy pocket-uk.uapack
cargo run -p uautonomy-hub -- serve   --data /srv/autonomy --app avtonomiia.apk
```

## Каталог

`catalog.json` = `{ "base_url": "…", "packs": [маніфести] }`. Файл пакета
лежить за адресою `{base_url}/{id}/{path}`. Якщо `base_url` порожній, береться
тека, де лежить `catalog.json`. Кожен телефон чи хаб з увімкненим «Обміном»
віддає `/packs/catalog.json` зі своїми пакетами, тож пакети розходяться
телефон-телефон без інтернету.

Офіційний каталог — випуск `packs` у GitHub Releases проєкту
(`https://github.com/louraider/UAutonomy/releases/download/packs/catalog.json`),
його застосунок відкриває за замовчуванням. GitHub Releases безкоштовні й
підтримують докачку; межа — 2 ГБ на файл, тому моделі лежать на Hugging Face,
а в каталозі для них є пряма адреса (`files[].url`) і SHA-256 з LFS.

## Карти

Карти векторні: PMTiles зі схемою OpenMapTiles. Ядро читає тайли
(`pmtiles.rs`), застосунок малює їх через `vector_map_tiles`, інтернет-тайлів
немає. Пакети збирає `tools/maps/build_maps.sh` у GitHub Actions
(workflow «Пакети»):

1. OSM України з Geofabrik (`tools/maps/fetch_ukraine.sh`). Geofabrik
   іноді не пускає раннери GitHub; тоді скрипт бере всі області з
   download.openstreetmap.fr (цілого файлу України там немає), звіряє MD5
   і зливає їх `osmium merge` + `osmium time-filter` (по одній, найновішій
   версії кожного об'єкта).
2. Карти повні, як у відкритому OSM: дані й так публічні, тому нічого не
   прибираємо. Фільтр `tools/maps/exclude-tags.txt` лишився необов'язковим
   (`FILTER_INFRA=1`, у workflow — галочка `filter_infra`).
3. Вирізати область за `bbox` з `regions.rs` (`osmium extract`).
4. `tilemaker` → `.pmtiles` z0–z14. Моря немає (шари з shapefile вимкнено), лише дані OSM.
5. `uautonomy-hub pack --kind map --region <id>`.

### Карти в браузері (iPhone, ноутбук)

Сервер Wi-Fi-обміну віддає `/map`: сторінку з MapLibre GL JS, стилем
OpenMapTiles (`webmap.rs`), тайлами `/map/tiles/<область>/{z}/{x}/{y}.pbf`
і гліфами Noto Sans (латиниця й кирилиця). Усе вбудовано в ядро, тож і
роздавач, і той, хто дивиться, обходяться без інтернету. tilemaker не
записує межі в заголовок PMTiles і кладе назви в `name:latin`, тому межі
беремо з області, а підписи з `name:latin`.

## Енциклопедії Kiwix (ZIM)

Списки енциклопедій лежать у `tools/packs/kiwix.json`. Workflow «Пакети»
запускає `tools/packs/kiwix_pack.py`, який бере найновіший файл кожної з
download.kiwix.org, а розмір і SHA-256 читає з `.meta4`. Файли ZIM ми не
копіюємо: у каталозі для них прямі посилання (Kiwix сам перенаправляє на
дзеркала, докачка працює). Файли до 700 МБ workflow завантажує повністю,
звіряє SHA-256 і відкриває нашим читачем (`uautonomy-hub zim-check`).
Якщо якоїсь назви на Kiwix немає, запис пропускається, а в журналі
з'являються схожі назви.

Оновлення автоматичні: щопонеділка (05:23 UTC) workflow за розкладом
порівнює найновіші ZIM із тими, що в опублікованому `catalog.json`
(`tools/packs/zim_changes.py`, за SHA-256). Якщо Kiwix випустив новий
місяць, збираються лише енциклопедії: каталог перепідписується ключем
`PACK_SIGNING_KEY` і викладається у випуск `packs`, а карти й модель
переходять із попереднього каталогу без перезбирання. Без змін нічого не
збирається і не публікується. Вручну те саме: Run workflow з `regions=none`.
GitHub вимикає розклад, якщо в репозиторії 60 днів не було комітів; тоді
його вмикають кнопкою «Enable workflow» в Actions.

Бібліотеки zimgit (water, medicine, post-disaster) у каталог не входять: у
них дві HTML-сторінки, решта — PDF, а наш пошук і ШІ поки читають лише HTML.

## Моделі

Каталог моделей (`models.rs`) — JSON з вимогами до ОЗП. Застосунок
рекомендує модель за залізом (`hardware::recommend`), з тих, що є в
каталозі пакетів:

| Пристрій | Модель | Примітка |
|---|---|---|
| Телефон, 3,5–6 ГБ ОЗП | Gemma 4 E2B | за бажанням |
| Телефон, 6+ ГБ | Gemma 4 E2B | вмикається сама; моделі для ПК телефонам не пропонуються |
| ПК, 8–15 ГБ | Gemma 4 E4B | легкий варіант |
| ПК, 16+ ГБ | MamayLM 12B (v1.0, Q4_K_M, 7,3 ГБ) | основна; найкраща в тестах, без небезпечних відповідей |

Якщо MamayLM немає в каталозі або вона не влазить на диск, ПК бере E4B,
а без неї — E2B. Gemma 4 26B A4B лишається в каталозі моделей, але не
рекомендується (лише трохи краща, 17 ГБ і не влазить у 16 ГБ відеопам'яті).

Які моделі публікуються, описано в `tools/packs/models.json` (репозиторій і
файл на Hugging Face, а також SHA-256 файлу, який ми перевіряли). Workflow
«Пакети» з `models=all` створює для кожної теку пакета: ваги лишаються на
Hugging Face, а файли з `attach` (для MamayLM: `NOTICE`, копія Gemma Terms of
Use і Prohibited Use Policy з `tools/packs/licenses/gemma/`) публікуються
у випуск `packs` і входять у пакет. Так вони є в кожній копії моделі,
зокрема переданій через «Обмін», як вимагає розділ 3.1 Gemma Terms of Use
(див. `docs/licenses/mamaylm.md`). Будь-який `.gguf` / `.litertlm`
можна додати вручну на вкладці «Помічник».
