# Ключі підпису

У проєкті два постійні ключі. Обидва створено 2026-11-24 на ПК власника, у
теці `.signing-keys/` робочої копії репозиторію (вона в `.gitignore` і в
`.git/info/exclude`). У репозиторії лежать лише публічні частини.

| Ключ | Що підписує | Приватна частина | Публічна частина |
|---|---|---|---|
| Пакети й каталог (Ed25519) | `manifest.json` кожного пакета, `catalog.json` | `pack-signing.key` → секрет `PACK_SIGNING_KEY` | `core/crates/uautonomy-core/assets/keys/trusted.json` |
| APK (RSA 4096, PKCS12, псевдонім `uautonomy`, до 2054 р.) | Android-застосунок | `android-release.p12` + `android-keystore-password.txt` → секрети `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD` | SHA-256 сертифіката: `66:7F:F3:72:53:88:91:1F:70:88:DA:AE:87:A6:55:1C:83:3D:FA:2A:B1:B8:A9:F5:BA:5F:60:BA:FA:FD:56:BA` |

## Чому це важливо

- **APK.** Android ставить оновлення лише з тим самим ключем. Якщо ключ
  загубиться, усі, хто вже встановив застосунок, не зможуть оновитися без
  видалення (а з ним зникнуть завантажені пакети). Якщо ключ украдуть, можна
  роздати підроблене «оновлення».
- **Пакети.** Хто має приватний ключ, може роздати «перевірену» шкідливу
  картку, і застосунок її прийме. Без ключа підмінити пакет неможливо, навіть
  через сусідній телефон чи флешку.

## Секрети GitHub

Settings → Secrets and variables → Actions → New repository secret:

| Секрет | Вміст |
|---|---|
| `PACK_SIGNING_KEY` | увесь текст файлу `pack-signing.key` (64 hex-символи) |
| `ANDROID_KEYSTORE_BASE64` | увесь текст файлу `android-keystore.base64.txt` |
| `ANDROID_KEYSTORE_PASSWORD` | увесь текст файлу `android-keystore-password.txt` |

CI (`ci.yml`) збирає окремі APK під arm64-v8a, armeabi-v7a і x86_64 і підписує
кожен постійним ключем (оновлення з колишнього універсального APK працює: той
самий ключ і більший versionCode); на
`main` без секретів збірка падає, щоб не роздати APK з debug-ключем. Workflow
«Пакети» підписує кожен пакет і `catalog.json` і не публікує нічого без
`PACK_SIGNING_KEY`; перед публікацією він перевіряє каталог вбудованими
ключами, тож розбіжність секрету й `trusted.json` одразу видно.

## Резервні копії

Після того як секрети додано, теку `.signing-keys/` треба:

1. Скопіювати щонайменше у два місця офлайн (наприклад, дві флешки в різних
   місцях) і в менеджер паролів, якщо він є.
2. Видалити з робочої копії, щоб її не зачепили синхронізація, бекап у хмару
   чи випадковий `git add -f`.

Ключі не можна відновити з GitHub: секрети там лише для запису.

## Ротація й відкликання

- **Ключ пакетів** можна замінити: додати новий публічний ключ у
  `trusted.json`, випустити застосунок, перепідписати каталог новим ключем, а
  в наступному випуску прибрати старий. Якщо ключ скомпрометовано, старий
  ключ треба прибрати з `trusted.json` у терміновому випуску застосунку.
- **Ключ APK** замінити не можна без перевстановлення в усіх людей
  (Android key rotation працює лише через Google Play). Тому його бережемо
  найсуворіше.

## Локальна збірка з ключем

`app/android/key.properties` (у `.gitignore`):

```properties
storeFile=C:/шлях/до/android-release.p12
storePassword=…
keyAlias=uautonomy
keyPassword=…
```

Або змінні середовища `UAUTONOMY_KEYSTORE`, `UAUTONOMY_KEYSTORE_PASSWORD`.
Без них реліз підписується debug-ключем із попередженням.

## Власні пакети для свого хаба

Хаб може довіряти ще й вашим ключам: `uautonomy-hub keygen мій.key` створює
ключ, `UAUTONOMY_TRUSTED_KEYS=<публічний hex>` додає його хабу. Застосунок на
телефонах таким пакетам не довіряє, лише ключам із `trusted.json`.
